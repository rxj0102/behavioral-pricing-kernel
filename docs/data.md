# Data

Status: Phase 1 (amended). Only the synthetic source has been run. No real market data has been ingested, because the build sandbox network policy blocked every external host and no WRDS credentials exist. Nothing produced from synthetic data may be reported as an empirical result.

## Data decision

- WRDS (OptionMetrics): not available, no credentials. The adapter exists (availability check only) and reads WRDS_USERNAME from the environment. Credentials are never hardcoded, printed or logged.
- Owner decision: free sources only, no paid data.
- Real fallback: a daily snapshot of the free CBOE delayed SPX chain, collected going forward. The sample will be short and will not contain 2008 or 2020. This limits what H1 to H4 can support and the paper will say so. The parser is written but tested only on a hand-built fixture, see below.
- Synthetic Heston panel: used only for method validation (identification study, unit and integration tests).

## Option panel schema

Columns: date, dte (calendar days to expiry), strike, cp (C or P), bid, ask, open_interest, spot, rf (continuously compounded risk-free rate). Every source maps into this schema (src/bpk/data/schema.py).

## Synthetic panel

Generated by src/bpk/data/synthetic.py. Two pricing modes (config synthetic.pricing_mode):

- heston_q: plain Heston prices under the risk-neutral measure (semi-closed form, src/bpk/data/heston.py).
- behavioral_sdf (default): prices come from the physical return density times a known rank-dependent SDF. Physical density: Heston under P-dynamics (equity drift eta v, variance mean reversion kappa + lam), obtained by Fourier inversion on a fixed grid. SDF: m(y) proportional to exp(-gamma y) times the derivative of the Prelec weighting function at the survival probability of y, with curvature alpha_t = clip(alpha0 - delta s_t, alpha_min, 1) driven by a synthetic sentiment AR(1) s_t. A closed-form location shift xi makes the same SDF price both the bond and the index, so put-call parity holds exactly with forward S exp((r - q) T). Details and formulas are in the module docstring; internal consistency is tested (densities integrate to one, E_P[m] = exp(-rT), E_Q[S_T] equals the forward, call prices match direct integration and are convex and decreasing in strike, trivial SDF leaves the density unchanged, CRRA kernel monotone and weighted kernel not).
- Known simplification: the daily state path uses plain Heston P-dynamics, while the pricing density is that density shifted by xi. xi is stored per date and maturity in the sdf truth table (about 0.3 percent at 21 days for the default parameters) and measures the gap.
- Generating parameters (Heston, SDF gamma, alpha0, beta, delta, seed) are written to results/tables/synthetic_truth_params__synthetic_heston.json with the config hash, for the Phase 5 recovery test. Per-date truth (spot, variance, sentiment, alpha_t) and per-chain truth (xi) come from SyntheticHestonAdapter.generate and are never given to the cleaner.
- Quotes have a spread, a 0.05 tick, open interest that decays in moneyness, and injected defects: crossed quotes (0.2 percent) and missing asks (1 percent). State variance is floored at 0.008 and vol of vol is 0.4 (Feller satisfied) because a near-zero variance makes the density nearly singular and the Fourier inversion inaccurate.
- Because the default SDF is non-monotone by construction, the synthetic EPK is non-monotone by construction. The panel validates methods; it says nothing about markets.

## Cleaning

Implemented in src/bpk/data/clean.py, steps listed in its docstring. Every step is counted in aggregate and by moneyness bucket of ln(strike / spot).

- Forwards come from near-ATM put-call parity only: the reference is the median pair forward over the five pairs nearest to spot, then pairs within a 5 percent window vote by median, and pairs deviating more than 1 percent from that forward are rejected from the vote.
- Only out-of-the-money options are kept (puts below the forward, calls at or above it).
- Quotes are never dropped for lacking a call or put counterpart, so wing quotes survive (tested). The earlier version dropped such quotes in a parity step; that step was removed and its large drop count in the first committed table was an artifact of that rule.
- Output files in results/tables: cleaning_stats__SOURCE.csv (per step) and cleaning_stats_by_moneyness__SOURCE.csv (step by bucket). Each begins with comment lines holding the source, config hash, requested and observed date range, and raw and clean row counts. A test checks these. The config hash covers the seed, data window, source, horizon, synthetic and cleaning sections (not output paths).
- Fast-config outputs go to results/tables_fast (git-ignored). Only default-config tables are committed.

## CBOE delayed chain (unverified)

src/bpk/data/cboe.py parses an assumed JSON layout. It has NOT been run against the live endpoint because the build sandbox could not reach cdn.cboe.com. The existing parser test uses a hand-built payload and proves only that the parser matches my assumption.

Prepared, not yet run:
- src/bpk/data/cboe_schema.py checks a snapshot against the assumed layout (and reports every problem).
- scripts/freeze_cboe_fixture.py downloads one snapshot, stores the raw file in data_raw/cboe (git-ignored, never committed), refuses to continue if the schema check fails, and writes tests/fixtures/cboe_schema.json (key names and types) and tests/fixtures/cboe_structural_fixture.json (real layout with constructed values, no copied quotes). Option --terms also saves the CBOE legal pages locally for a person to read.

## Provenance

Every cached dataset is recorded in the manifest with source, series, date range, SHA-256 of the cached file, row count and retrieval date. A cached file whose hash differs from the manifest raises an error. Rebuilding with the same seed and config gives identical output (tested).
